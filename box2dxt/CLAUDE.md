# CLAUDE.md - Box2Dxt

Guidance for Claude Code (claude.ai/code) in the Box2Dxt member (`box2dxt/` in
the xTalk suite monorepo, published from there into its own repository).
Suite-wide rules: the suite root `CLAUDE.md`. Engine behaviour: the suite's
`docs/OXT-ENGINE-NOTES.md`, cited here as "engine note N.N". Open work: the
suite's `docs/WORK-PLAN.md`, not this file.

## 1. What this is

Box2D **v3.1.0** physics for **OpenXTalk (OXT)** and the xTalk family (also
LiveCode 9.6.3+), plus the **b2k Kit**, a pure-script game toolkit over it. The
family's ANCESTOR (handle tables, platform ids, packaged-extension install and
the exception firewall were born here). **Folded into the suite 2026-08-14**
(`git archive`; the old repository is now the published mirror): the unified
checker replaced this member's own (the oldest lineage, 220 lines against 840)
and found ~1550 violations - ~1520 non-ASCII characters, 29 `repeat with ...
step` loops in the platformer (OXT ignores the step, engine note 3.1; tile loops
would have placed 64x the tiles) rewritten as `repeat while` + explicit `add`,
the `.lcb`'s 33 foreign-decl `pI` parameters (spells the reserved `pi`) and one
bare `i` local. `MANIFEST.sha256` was added; three stacks were trimmed to the
720p budget (demo 660 and spike 700 to 640, the contraption builder's `kStackH`
760 to 640, viewport only); the holde-em spec moved to its own member.

```
Box2D v3.1.0 (CMake FetchContent, GIT_TAG v3.1.0)
  -> C shim       src/box2d_lc.c                  exports b2lc_* -> box2dxt.{so,dll,dylib}
  -> LCB binding  src/box2dxt.lcb                 raw b2*: metres, radians, y-UP, int handles
  -> the Kit      src/box2dxt-kit.livecodescript  b2k*: pixels, degrees, y-DOWN, control-backed
                                                  bodies, the frame loop (SINGLE SOURCE OF TRUTH)
  -> examples/*.livecodescript                    each embeds a synced copy of the Kit
```

- **C shim.** Box2D ids are by-value structs and there is no 64-bit foreign
  int, so ids live in handle tables and cross as **positive 32-bit ints** (0 =
  invalid; generation-tagged: a recycled slot cannot resurrect a stale handle),
  reals as `double`, booleans as `int`. `b2*_IsValid` makes a stale or 0 handle
  a harmless no-op. The **`b2lc_` prefix is historical and NEVER renamed**
  (binary stability across the OXT rebrand). `LC_ABI_VERSION` = **4** =
  `b2Version()`; bump it when the ABI changes.
- **LCB binding.** `library org.openxtalk.box2dxt` predates the family's
  `org.openxtalk.library.*` convention and stays (renaming would break every
  installed user for zero gain). `b2PascalCase`; body type `0=static,
  1=kinematic, 2=dynamic`. 376 public handlers over 373 `binds to` lines: 370
  into `c:box2dxt>` plus three POSIX binds (`_dlopen`, `_dlerror`, `_realpath`)
  that `b2LoadNativeLibHere` uses to preload the library by exact path on Linux.
- **The Kit.** 313 public `b2k*` handlers incl. the game modules.
- **Packaging.** `src/code/<arch>-<platform>/box2dxt.{so,dll,dylib}` (bare
  token; ids `x86_64-linux`, `x86-linux`, `x86_64-win32`, `x86-win32`,
  `universal-mac`; architecture FIRST, `-win32` for both bitnesses), committed
  and pinned by `src/code/MANIFEST.sha256`. The installed extension resolves
  `c:box2dxt>` via `the revLibraryMapping`; the dev fallback is a loose library
  beside a SAVED stack, mapped by `b2kEnsureNativeLib`.

Layout: `src/` (shim, `.lcb`, Kit, `code/` binaries, refreshed by
`tools/package-extension.py`) - `examples/` (six paste-and-run stacks) -
`tests/smoke_test.c` - `tools/` (`run-gates.sh` and its gates, the sync,
packaging and `make-release.py` tools) - `docs/` (user docs; `README.md` is the
doc map) - `dist/INSTALL.md` (packed by `make-release.py`) - `.github/workflows/`
(GENERATED by the suite's `sync-member-workflows.py`).

## 2. Rules for working here

1. **The Kit has one source.** Edit only `src/box2dxt-kit.livecodescript`, run
   `python3 tools/sync-embedded-kit.py`, commit the re-synced examples IN THE
   SAME CHANGE. Never hand-edit between `-- >>> BEGIN EMBEDDED KIT >>>` and
   `-- <<< END EMBEDDED KIT <<<`; register new embedding examples in the tool's
   `EXAMPLES`; exclude the embedded region when auditing an example. Why: a
   stale embed compiles and runs last week's physics; only `--check` sees it.
2. **Every KIT change adds or extends a self-test assertion AND bumps
   `kStHarnessV`** (the report header prints it, so a stale paste identifies
   itself). Example-only changes do NOT bump (Waves 1, 3, 6, 7 did not).
3. **Write assertions self-diagnosing.** Recorded base rate: **5 Kit bugs : 5
   harness bugs - expect first-contact arithmetic errors**; print what was
   observed. An assertion that fails on a healthy engine is worse than none:
   readback exactness is an observation, ordering or contract is the assertion
   (engine note 5.4).
4. **After a shim or `.lcb` edit run `python3 tools/check-lcb-signatures.py`**
   (since 2026-08-17): all 370 `binds to "c:box2dxt>...!cdecl"` declarations
   against their `LC_API` definitions (return type, arity, each parameter type),
   both directions, five refusal classes each mutation-tested. Why: the engine
   resolves by NAME and calls with whatever the declaration says, so a `CInt`
   promised where the shim returns `double` hands script a plausible number.
5. **Adding a raw handler:** validating `b2lc_*` in the shim -> `foreign
   handler` + public `b2*` wrapper -> bump `LC_ABI_VERSION` if the ABI changed
   -> a `tests/smoke_test.c` assertion -> `check-lcb-signatures.py` -> an entry
   in `docs/api-reference.md` (a new public Kit handler: `docs/kit-reference.md`).
   `tools/check-reference-docs.py` refuses a public handler either page never
   names, and a name a page keeps after it is gone (since 2026-09-24, when both
   pages were completed: they had fallen to 216/376 and 242/313). Shim stays
   warning-clean (`-Wall -Wextra`, `/W3` on MSVC).
6. **Stale handles never crash.** Every public handler tolerates a stale or 0
   handle and an empty control ref (getters return 0 or empty, actions no-op).
7. **Honesty.** Nothing compiles a `.livecodescript` headlessly here; the user
   tests in OXT. Say "verified statically; needs an OXT pass".
8. **Style and git.** Why-dense comments; per-task branch, draft PR, never push
   to `main` without permission.

## 3. LiveCodeScript / OXT gotchas (numbers are cited from code - keep them)

1. **No smart quotes anywhere**, even in a comment (engine note 1.4); the
   unified checker requires ASCII-only `.livecodescript` (UI glyphs are ASCII).
2. **Avoid names that shadow engine tokens**, even prefixed: `the uCat` /
   `the uMask` broke compilation and became `uHitChans` / `uOnChans`.
3. **Prefixes:** `u` custom property, `g` global, `t` local, `p` parameter, `k`
   constant. Public API: `b2PascalCase`, `b2kPascalCase`, `b2lc_snake_case`.
4. **Only the block `if` takes `end if`**; `\` continues a line. Balance
   counters false-positive on a continued `if ... then \` and a multi-line
   `else if` - verify by eye, do not "fix" valid code.
5. **`itemDelimiter` / `lineDelimiter` are mutable state** (engine note 2.3):
   set the delimiter immediately before parsing. 2026-09-09 (`51ac525`):
   `b2kAddBox`, `b2kAddBall`, `b2kAddCapsule`, `b2kAddPolygon`, `b2kReshape`,
   `b2kHinge`, `b2kWeld`, `b2kSlider`, `b2kWheel`, `b2kDrawPoly` now set comma
   first - under a tab, `item 1 of "512,246"` is the whole string, a hard throw
   into a Number-typed `.lcb` parameter (engine note 6.4); the contraption
   builder's Images panel reached it (a static finding). Eight
   contraption-builder handlers (`serializeText`, `refreshImagePanel` among
   them) now restore a borrowed delimiter around the narrowest span. **When
   that span makes OUTWARD calls, collect -> restore -> call**
   (`fireEmitter`/`fireTarget`, `refreshImagePanel`/`makeAction`); a restore
   at the end looks fixed and leaves the bug. Harness v32's
   `stTestCallerDelimiter` drives all ten under a caller's tab and prints
   whether a caller's delimiter reaches a called handler on that engine at
   all. **Win32, 2026-09-24, and Linux, 2026-09-25 (section 12): it does
   not** ("it saw comma"), and a Kit call left its caller's tab alone ("tab
   in, tab out"): on both, the itemDelimiter crossed a handler call in
   neither direction, the LiveCode dictionary's handler-local reading
   (engine note 2.3's counterpoint). So on Win32 and Linux the ten passed
   WITHOUT exercising the fix (the harness says so), and no cross-call leak
   this entry guards against, the Images panel's included, could have fired
   there. macOS: needs an OXT pass.
6. **Constants must be literals**; derive computed values at runtime.
7. **Command vs function.** A Kit COMMAND reports through `the result`
   (`b2kSpawnBox ...` then `put the result into tCtrl`); `get b2kSpawnBall(...)`
   throws at the call line (spike S11).
8. **Custom properties are the per-object datastore, all text**; booleans
   round-trip as the strings "true"/"false".
9. **Two coordinate systems, y flips.** Kit code calling raw `b2*` divides by
   `sScale` and negates y (`b2kForce` passes `-fy`).
10. **Dangling else.** A bare `else` after a single-line `if cond then stmt`
    binds to it and OXT reports "missing end if" at the handler end
    (`if c then s1` / `else s2` is fine). The checker flags it.
11. **Declare `local` only at a handler's top**; a nested one broke
    compilation of a whole script.
12. **Scrolled-group locs are SCROLL-ADJUSTED** on OXT, so per-frame world
    writes cancel the pan; `b2kCamOn` probes it and `b2kCamShiftX/Y`
    compensates. Hand-animate with `b2kSpriteMoveTo`, never `set the loc`.
13. **Object-type tokens are single words:** `import audioClip from file`
    compiles, `import audio clip` fails ("bad image type"); same for `videoClip`.
14. **Sensor/contact MESSAGES go to `b2kContactTarget`, not the frame target**;
    forgetting it gives silent sensors with zero errors (the micro-game shipped
    that way). Set both targets.
15. **Chain ghost rule:** an open chain of N points collides as N-3 segments;
    run every chain one segment past the surface on each side.
16. **Verdicts use windows or polls, never instantaneous reads.** Presence =
    poll `b2kOverlap` (it sees sleeping bodies); stomps = recent-state windows;
    one-shots = sensor events; external boosts go through `b2kPlayerJump` (a
    raw upward velocity on a grounded player is ground-snapped). Impact
    strength = speed-poll the LIGHT body after a build-settle grace.
17. **`b2kSetVelocity` WAKES the body**; never write velocity per frame to
    something meant to rest (the parked-shell bug).
18. **Two velocity-asserting bodies never share a path** (the asserts fight
    the solver); split patrol bands.
19. **A non-looping animation fires `b2kSpriteOnFinish` whoever started it**:
    if finish is wired to respawn, the hurt anim must be a LOOPING twin
    (`hurtpose`) and every `*HurtDone` gates on its own respawn lock.
20. **One-sided chain contacts judge by the CENTROID.** Restore masks only once
    the body has cleared the line (4x-window deadline); never park a solid
    within a player-height under a one-way deck.
21. **Filter bits:** xTalk `bitAnd`/`bitOr` are 32-bit and Box2D's default mask
    reads back as 2^64-1, so clamp mask round-trips to 4294967295. Bit 2^31 is
    the Kit's reserved `oneway` chain layer: `b2kDefineLayer` stops at 2^30 (31
    nameable layers) and `b2kSetMask` ORs `oneway` in. The shim accepts up to
    2^53-1 and silently refuses a whole call above it (see the ledger).
22. **Deleting a `switch` case hands the row to `default`**; keep an empty
    commented case where the default would misbehave (paired fall-through
    cases are legal).
23. **Sprites follow position only; they do not rotate.** Rotating bodies must
    be spawned GRAPHICS (why the slingshot is sprite-free).
24. **Mixed sprite grids never share a level raw**: normalise with
    `b2kSheetScale` (the 70px `enemies.png` at 0.9 into the 64px platformer).
    Family B/C frame names carry `.png`; Kenney `-default` sheets do not.
25. **Optional sheets gate their makers on a capability flag**
    (`gSpooksOK`/`gToysOK`); a missing sheet degrades silently and the level
    stays completable.
26. **Art facing polarity is statically unverifiable**; pick a convention, list
    it in the example's verify list, let the OXT round report mirrored sprites.
27. **`the result` is consumed by the NEXT command**; capture it immediately
    after every `b2kSpawn*` or maker call.
28. **Size the hitbox to the VISIBLE art**, feet-aligned, and read the body's
    real half-height, never a constant: an 88px capsule over a ~76px character
    bumped bricks the head never touched.
29. **A `constant` must be declared BEFORE its first use, lexically** (engine
    note 1.3): the L4 lava serpent's `sin(kPI * tP)` with `kPI` declared ~900
    lines below evaluated to 0 and the serpent never rose (confirmed in OXT).
30. **An unqualified control in a delayed handler resolves against THE
    DEFAULTSTACK** (engine note 5.3), which after `send ... in` is whatever is
    frontmost. Pin first: `set the defaultStack to the short name of this
    stack`. A guarded form (`if there is a graphic ...`) silently stops working
    instead of throwing. `pfCardFadeStep`/`sgCardFadeStep` carry the pin (found
    by the suite's `tools/check-timer-stack-pin.py`; needs an OXT pass); so must
    `send "nextLevel" to me in 80 milliseconds`. DOCUMENTED behaviour: no
    handler here has been watched misfiring (a Linux 2026-08-18 throw filed
    against it traced to another bug).
31. **A throw inside the frame is SILENT.** `b2kStep`/`b2kStepOnce` run body
    sync, input, player, sprites, camera, contact/sensor dispatch and your
    `b2kFrame` inside one `try` with an empty `catch` (deliberate: it
    guarantees the `unlock screen`), so an error drops the rest of that
    frame's work with no message. Spike v1's S8 chain-phase failure
    (2026-06-10) vanished this way; the Wave 1 door (2026-06-12 OXT round)
    ran an unproven `b2kDisable` ahead of the proven `b2kMoveTo` park, so a
    throw there would have skipped the park unseen (reordered; harness v9 later
    showed both work). A throw serializes "redundant" calls: put proven
    calls first, give a risky call its own `try`, and log from its `catch`.

## 5. Kit design decisions (the as-built contract)

- `b2kStep` reschedules with ITS OWN generation `pGen`, not the live `sGen`
  (a rebuild inside a frame changes `sGen`; rescheduling with it clones the
  loop). Box2D exposes only the LAST step's events and a frame runs 0..n
  steps, so the Kit harvests events per step.
- `b2kOverlap` reads fattened broadphase boxes (~0.1 m), so a pad's own floor
  overlaps it forever; `b2kOverlapMoving` filters statics.
- Teardown wipes sprites BEFORE the viewport dissolves (stored long ids embed
  the group path).
- The player controller is a SINGLETON (flat `sPlay*` locals).
  `b2kPlayerControl false` = observe-only (no velocity or animation writes; the
  maxFall clamp stays live). The ground probe is suppressed while the
  controller's own jump rises. Tuning survives `b2kClear` and dies with
  `b2kTeardown`/`b2kPlayerRemove`. Owned bodies get bounce 0; coyote/buffer
  windows run on the SIM clock; `land` needs 3+ airborne ticks.
- Audio = imported `audioClip`s (one at a time) + `b2kToneMake` (pure-script
  WAV). Mute and sounds survive `b2kTeardown`; a play failure trips a dead flag
  (`b2kSoundStatus()`), never an error.

## 6. Performance: the single-threaded envelope and playbook

FFI, script and rendering share ONE interpreted thread at ~60 fps (~16 ms).
Envelope: dozens of active bodies plus a few dozen animated sprites (~25 LIVE
sprites sit near the ceiling; inert tiles are nearly free). Degradation ladder:
lower anim fps -> fewer awake bodies -> render at 30 fps with the sim still at
60 Hz; never lower the sim rate. A blocking call (`answer`, `wait`, sync I/O)
stalls the world.

Cost order: **interpreter ops > FFI round-trips > property-set redraws.** Each
rule was earned by a measured regression:

- One hero snapshot per frame (`gHeroPX/PY/State`); one clock read per pass.
- HUD/field text at 4 Hz max, only on change (the biggest avoidable cost).
- Build once, write on change: never `create` mid-game; POOL effects and park
  them off-world; pre-warm sheet frames first shown mid-game with
  `b2kSheetEnsureIcon` (a lazy slice costs ~250 ms per frame name).
- Skip redundant property sets; every idle tick gates in one compare
  (`gPlantN is 0`); resolve at bind/set time, never per use.
- Let bodies sleep (gotcha 17); polls see sleeping bodies anyway.
- Defer world rebuilds out of the physics frame (`send "nextLevel" to me in 80
  milliseconds`) with a stale-send guard and the defaultStack pin (gotcha 30).
- Park before disable: move a body off-world first, then disable.
- Raw handles in hot paths; friendly wrappers for event and build paths.

## 7. Layout, game-design and asset laws

- **Layout law:** every interactive beat gets ~100px of clear air; widen the
  world rather than squeeze; when re-spacing, move each beat WHOLE and keep
  deliberate pairings at their offsets.
- **Chain solid span = art span:** check `sorted(xs)[1:-1]` against the tile
  extents.
- **Gates are structural** (floor to ceiling); **scenery builds before actors**;
  **never `b2kCamGoto` before `b2kCamBounds`**; **no sub-capsule slots between
  statics** (boundary slabs are ~256px thick).
- **Knockback vs respawn:** contact damage = `b2kPlayerHurt` + mercy
  (`b2kPlayerHurtIs()` gates hazards); only lethal falls respawn.
- **Self-counting totals:** makers increment totals as they BUILD.
- **Ladder and water zones are world state** wiped by `b2kClear`. A swim pool
  is a RAISED basin (`b2kCamBounds` clamps at the world bottom); `swimJump`
  alone sets the escape height, `swimGravity` only the between-stroke sink.
- **Hazard mercy:** a riser never rises under the hero's feet; proximity
  hazards telegraph (mimic wake >= 110px); unkillable hazards follow "the saw
  rule" (skip or time them).
- **Versioned chrome:** bump `kUIVersion`-style tags when built chrome changes;
  bump the newest-cue guard in `*MakeSounds` when adding a tone.
- **Assets:** sprite-only visuals (plain graphics only as invisible physics
  hosts; the no-asset fallbacks are frozen); measure art (alpha) before placing
  it; never mix raw grids in one level; spook (`enemies.png`) skins fill their
  frames, so the bind offset is `pFullH/2 - frameH*0.9/2`, not the FOES
  soft-bottom sink (~9px float); the `conveyor` tile is a single frame (the belt
  is a polled vx zone); the background scenes are 100% opaque (measured), so
  single-layer parallax drift is the ceiling until transparent overlay art
  exists; `Spritesheets/spritesheet_complete.xml` is an orphan (its
  `sprites.png` was never uploaded).

- Seven levels: L1 Green Hills, L2 The Works, L3 Frozen Citadel, L4 Haunted
  Hollow, L5 Scorched Dunes, L6 Cavern Depths, L7 Stone Keep (a vertical
  climb). **Feature development is FROZEN.** An 8th level, "Clocktown", was

  COUNT; bronze/silver/gold tiers (1/2/3) feed a separate bonus `gScore`.
- Transition card (`pfCardShade`/`pfCardText`) and boot title: card-level

  `pf_*` (`pfWipeStage` deletes those). Hero select (1-5) is on the title only.
  Per-level screenshots were rejected (levels are ~6,400px scrolling worlds).
- `audit-platformer.py` skips the vertical L7 and ignores `pfMakeSnake`/
  `pfMakeSerpent` (harmless); it reported 0 findings on 2026-09-10.
- **Parked by D-19 (2026-08-27, "triggers stand"; nothing scheduled):** Wave 8
  builder cross-pollination (sprite parts, the player as a placeable kind);
  `b2kScene*` promotion only if a second game needs it (the retired micro-game's

## 9. The contraption builder (`examples/box2dxt-contraption-builder.livecodescript`)

The flagship example (~575 KB; its embedded Kit spans lines ~40 to ~5722).
- It builds its own UI on open, tagged `kUIVersion` (**bump it when built
  chrome changes**). Parts are graphics backed by Kit bodies (`tagPart` sets
  `uKind`/`uColor`, calls `registerKind`) listed in `gParts`; joints live in
  `gJ*` arrays. `on b2kFrame` fans out to the `update*`/`render*` ticks and
  `tickHud`; build mode redraws through `renderBuild`.
- Fans, magnets, the laser and the goal have NO body: `kindHasBody` must return
  false for exactly those four, or body-only code (`b2kAngle`, `reseatDragged`)
  errors. `kindIsDynamic` lists what fans/magnets push.
- Save/load is text: `serializeText` emits `part`/`joint`/`world` records;
  `partSpecial`/`applyPartSpecial` pack and restore a KV string
  (`"ldr=45;tpw=700"`); `partLine` saves the `loc`, except the laser, which
  saves its emitter (point 1 of the beam).

**Recipe: adding a part kind** (copy `fan` or `laser`): (1) add the id to
`kShapeTools`/`kSpecialTools`/`kTerrainTools` and its `...Labels`, bump
`kUIVersion`; (2) `placePart` case -> `place<Id>(pX,pY)`; (3) `place<Id>`
creates the graphic, sets `u*` props, `tagPart`s it, spawns a body for body
kinds; (4) `registerKind`/`unregisterKind` if it needs a per-frame tick; (5)
`update<Id>s` in `on b2kFrame` (and `renderBuild` if it refreshes in build
mode); (6) `kindHasBody` and `kindIsDynamic`; (7) inspector: `partProps`
(<= `kPropRows` = 10 keys per tab), `propGroup`, `propLabel`,
`adjustPartProp`, and `currentPropValue`/`applyPropValue` for type-in values;
(8) `partSpecial`/`applyPartSpecial` (keys unique within the kind), and
`partLine` if the anchor is not the `loc`; (9) `toolGlyph`, `toolHelp` (title +
long help), `niceName`/`friendlyKind`; (10) gates clean, then the user tests in
OXT.

Invariants: every kind has `placePart`/glyph/`toolHelp`/`niceName`; every
`partProps` key has `propLabel` + `adjustPartProp`; no tab over 10 rows;
save-keys unique per kind; selection is non-destructive (`uSelFg`/`uSelLine`).

## 10. The self-test harness and the suite fold

`examples/box2dxt-selftest.livecodescript`, **`kStHarnessV` 32**: 387
`stAssert` call sites in 52 test handlers (385 execute in a green run), driving
the real Kit (paused world, `b2kStepOnce` hand-stepping, `b2kInputInject`
keys). The first 39 handlers are BEHAVIOUR tests; the 13 added at v23 are
shallow "Kit API coverage" sections, and a handler that earns a real lesson
