# oscxt

**Open Sound Control for OpenXTalk / the xTalk family (and LiveCode 9.6.3+).**

oscxt builds and reads OSC messages and bundles: the network language of TouchOSC, QLab,
Resolume, SuperCollider, Pure Data, Max and most show-control software. It is
[tinyosc](https://github.com/mhroth/tinyosc) (ISC, vendored) behind the family's flat C shim
and a thin LCB layer. It is a codec: the network is the engine's own UDP sockets.

```
tinyosc (vendored, ISC)
   |- C shim   src/osc_shim.c  ->  oscxt.{so,dll,dylib}     (ABI: osc_*, v2)
        |- LCB binding  src/osc.lcb     (org.openxtalk.library.osc; public osc*)
             |- examples/osc-helpers.livecodescript   (send and route over UDP)
```

It is the OSC third of ShowControl, which joined the suite on 2026-11-21 as **oscxt**,
**midixt** (realtime MIDI) and **artnetxt** (Art-Net lighting). The library id, every handler
and the helpers are ShowControl's, so a stack written for ShowControl's `osc` extension keeps
working.

## What it can do

- **Build** a message from an address and typed arguments: int32, float32, float64, int64,
  timetag, string, blob, and true, false, nil and impulse; bundles of messages and bundles,
  with a timetag.
- **Read** any datagram into an array (address, type tag, arguments; or a bundle's timetag
  and messages, nested), and refuse anything that is not OSC, with a reason.
- **Match** an address against an OSC 1.0 pattern (`?`, `*`, `[a-z]`, `[!a]`, `{a,b}`).
- **The family's rules.** No thread and no callback (rule 1); the shim validates everything
  before tinyosc sees it, and reads a network datagram only at offsets a bounds-checked
  scan proved (rule 2); every builder and parsed message is a generation-tagged handle
  script never sees (rule 4).

What it does not do: open sockets (the engine does), OSC over TCP or SLIP, or schedule a
bundle by its timetag (the timetag is read and written, not acted on).

## Quick taste

```livecodescript
-- with examples/osc-helpers.livecodescript pasted into the stack script
on openCard
   accept datagram connections on port 9000 with message "socketReceived"
end openCard

on scOscMessage pAddress, pArgs, pSender
   if pAddress is "/1/fader1" then set the thumbPosition of scrollbar "Volume" to pArgs[1] * 100
end scOscMessage

on mouseUp
   local tArgs
   scAddArg tArgs, "f", the thumbPosition of scrollbar "Volume" / 100
   scOscSend "192.168.1.20", 7000, "/composition/master", tArgs
end mouseUp
```

[docs/getting-started.md](docs/getting-started.md) carries on from there.

## Status

Joined the suite on 2026-11-21. What has run, and where:

- **Natively**, on x86_64 Linux: every export, the wire-format vectors, and a mutation
  fuzzer over the parser and every getter, clean under ASan/UBSan; a clean-room Python codec
  written from the OSC 1.0 specification agrees with every vector. Every fix oscxt made to
  ShowControl's code has a test that failed against it.
- **On an engine**, the same day, OXT-Beyond's headless engine (9.7.1-OXT, Linux x86_64),
  over a locally built library: the LCB suite under lc-run, and the Script suite in the
  standalone engine with `-ui` (the Script-to-LCB boundary, the helpers, the shipped
  self-test, real UDP through the engine's sockets, and interop with an independent OSC
  peer).
- **Not yet:** no desktop IDE has loaded it, and no engine on Windows, macOS or Android has
  run it: there it is verified statically; needs an OXT pass. No library is committed under
  `src/code/` yet; the suite's release-binaries dispatch lands them.

