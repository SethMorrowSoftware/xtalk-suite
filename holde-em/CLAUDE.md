# CLAUDE.md - holde-em

Guidance for Claude Code (claude.ai/code) when working in `holde-em/`. Read it
before touching anything. Where this file and the suite root `CLAUDE.md`
conflict, this file wins inside `holde-em/`.

## 1. What this is

**holde-em** is serverless online no-limit Texas Hold'em for OpenXTalk (OXT) and
the xTalk family (also LiveCode 9.6.3+). It is a pure-script capstone APP: no
native code and no LCB live here. It composes TorrentXT (`bt*`, rp1 needs ABI
v8+), SodiumXT (`sx*`), OnionXT (`ox*`, optional, CARRIED inside the stack since
v0.25.2 on 2026-08-27) and the Box2Dxt Kit (`b2k*`, optional presentation).

ONE paste-and-run stack, `src/holdem.livecodescript`, holds the game, its
self-test harness, the diagnostics `heProbeSodium` / `heProbeTorrent` /
`heProbeKit` / `heProbeSounds`, and the carried onionxt layer between
`tools/sync-demo-embeds.py` sentinels. Current: `kHeVersion` 0.25.3,
`kHeHarnessV` 45, `kUIVersion` 15.

`holdem-spec.md` is the contract. Where code differs, the code wins and the
spec is updated. Because chips may someday carry value, read spec 2 (threat
model), 13 (value-readiness) and 16 (security checklist) before writing any
protocol code; section 16 is law. `README.md` is the front door and carries the
phase status table.

Layout:

```
src/holdem.livecodescript  the whole thing: game + harness + probes + carried onionxt
holdem-spec.md             the design contract (sections 1-16, numbers cited from code)
tools/                     run-gates.sh (THE gate list), the unified checker, the docs
                           and layout gates, seven KAT mirrors, logic-fuzz, the execution gate
assets/cards/, assets/sounds/  vendored Kenney CC0 art and audio (see each NOTICE.md)
.github/workflows/gates.yml    GENERATED by the suite's tools/sync-member-workflows.py
```

## 2. Rules for working here

1. **Honesty law.** Anything visual, timed, socket- or extension-touching gets
   "verified statically; needs an OXT pass" until the user confirms it in the
   IDE (Tor legs: "+ live-Tor pass"). The interpreter is not the engine.
2. **The unified checker is never edited here alone.** `tools/check-livecodescript.py`
   is byte-identical across members (the suite's `check-checker-drift.py`; every
   rule fixture-tested by `test-checker.py`). The hold-em lineage checker was
   retired 2026-08-15; its checks are unified checks 13-21. Two were NOT ported,
   because fleet engine evidence contradicts them fleet-wide: H6 (chunk of an
   array element) and H7's blanket bitwise ban. Both stay member law, held by
   review. Check 13 flags only the function-call form `bitXor(a, b)`; check 15
   fires only when the catch body REFERENCES the undeclared variable.
3. **Every script-level declaration sits above the first handler** (all of them
   are above `on preOpenStack` since v0.24.1). An undeclared name evaluates to
   its own spelling and OXT resolves script-level names by lexical position
   (suite engine notes 1.2, 2.1).
4. **Pure logic stays pure (H5).** Rules, shuffle, fold and settlement live in
   handlers that take values and return values, with no UI reads. That is what
   lets the KATs mirror them and the harness pin them.
5. **Add a harness section to `heTestRunAllSections`**, never to one entry
   point. Bump `kHeHarnessV` on every engine-behaviour change AND whenever
   assert sites are added (v0.24.5 added five sites without a bump, so "v41"
   names two totals; v43 -> v44 on 2026-09-10 covered the four wire-arity
   sites, v44 -> v45 on 2026-09-24 section 24's). Call sites are not checks
   (at v40, 374 sites reported 507 checks): the next engine run RECORDS the
   v45 total rather than matching 667.
   `kHeHarnessV` is printed in the report header so a stale paste identifies
   itself. Asserts are self-diagnosing: print what was observed against what
   was expected, never a bare FAIL, and write first-contact tests to debug
   themselves (expect arithmetic slips on first engine contact).
6. **Bump `kUIVersion` on every chrome change** (a control added, moved or
   resized). `heBuildTable` rebuilds only when the stack's `uHeUIVersion`
   differs; otherwise a SAVED stack keeps its old chrome and only rehydrates
   its script locals (`heRehydrateChrome`). `tools/check-table-layout.py`
   holds the geometry.
7. **Never guess an FFI signature.** Read the sibling's `docs/api-reference.md`
   (sodiumxt's, torrentxt's, onionxt's, box2dxt's). v0.4.0 found `sxHash` needs
   an output length: `sxHash(data, 32)` for BLAKE2b-256, `sxHash(data, 64)` for
   the ristretto from-hash input. `sxSignKeypairFromSeed pSeed, out rPub, out
   rSec` is a COMMAND with out-params. Hole delivery is `sxSeal` / `sxSealOpen`.
8. **Security rules (spec 16 is the checklist).** `sxMemEqual` for every secret
   comparison; `sxRandomBytes` for anything unguessable (engine `random()` never
   touches dealing or keys); domain-separated `"HOLDEM-<PURPOSE>-v<N>|"` hashes;
   verify-then-parse, drop and log; fresh per-hand randomness and per-table
   session keys; long-term keys only sign.
9. **Performance playbook.** One interpreted thread at ~60 fps (16 ms). Pool
   everything at build; `b2kSheetEnsureIcon` every frame that can appear (a lazy
   slice costs ~250 ms); HUD at most 4 Hz and only on change; idle costs one
   compare; no per-frame crypto or FFI (the 52 deal-time mults are fine); defer
   world changes with `send ... in 80 milliseconds` plus a stale guard.
10. **The ui-kit gate EXEMPTS this stack** (the game table on the b2k Kit); D-18
   made the game-canvas exemptions PERMANENT on 2026-08-27. The `he*` prefix is
   registered in the suite's `tools/check-handler-calls.py`. Kit delivery:
   `start using` the installed `box2dxt-kit`; `heKitTryInit` degrades to the
   flat UI without it.
11. **Git:** task branch, scoped commits; comment the WHY, densely.

### House laws H1-H9 (cited by number from the source)

- **H1.** Native sessions bracket the stack's life: `openStack` starts,
  `closeStack` tears down (`heNetStop` -> `btStopSession`; `oxShutdown` when
  this stack opened the tor control connection, `gOxCtlUp`). OXT has no
  deterministic extension-unload hook.
- **H2.** One poll drain per tick (`btPoll` + `btRp1Poll`, ~250 ms), never in
  `b2kFrame`, never per frame.
- **H3.** Everything is `Data` at the SodiumXT boundary: `textEncode(..., "utf-8")`
  in, `textDecode` out, hex only for display and transcript fields.
- **H4.** Crypto failures throw, so every open sits in `try`/`catch`; the catch
  treats the message as hostile: drop and log, never retry.
- **H5.** Pure logic is values-in/values-out, with no UI reads and no reliance on
  `the result`.
- **H6.** Never take a chunk of an array element (`byte i of tA[j]`); copy it to
  a local first. Found on the first OXT pass, in the seed-XOR path. Deliberately
  NOT a gate: riptide/onionxt/box2dxt/nocloud chunk array elements in
  engine-passed code; what threw here was FFI-bridged binary. **Corollary
  (v0.1.1):** hex-encode FFI binary at the edge (`sxBin2Hex`); raw `Data` exists
  only inside `sx*` call expressions.
- **H7.** No bitwise operators: `bitXor` threw at v0.4.1. Use `heByteXor`, an
  8-iteration div/mod XOR.
- **H8.** Declare every catch variable as a local. `heProbeSodium`,
  `heProbeTorrent`, `heDeckFromStreamKey` and `heNetStart` shipped without it
  at v0.10.x and threw a second error that masked the first.
- **H9.** No `the (expr) of obj` (computed property names). Since v0.14.0 one
  `uHeAvatarPaths` property holds line N = seat N (unified check 17).

## 3. Gotchas and traps

### 3.1 Carried gotchas (Box2Dxt numbering kept; the spec and source cite them)

Gaps in the numbering are platformer-only lessons left behind. Engine behaviour
itself is catalogued in the suite's
[docs/OXT-ENGINE-NOTES.md](https://github.com/SethMorrowSoftware/xtalk-suite/blob/main/docs/OXT-ENGINE-NOTES.md).

1. **No smart quotes** anywhere, comments and literals included (gated; suite
   engine note 1.4).
2. **Token shadowing.** A name whose stem is an engine token breaks compilation
   (`uCat`/`uMask` were renamed); a name that EQUALS a token is the token: `tAb`
   read as `tab` (v0.4.2, `heByteXor` -> `tWorkA`). Unified check 14 (engine
   note 1.5).
3. **Prefixes:** `u` custom property, `g` script-local global, `t` local, `p`
   parameter, `k` constant; the public surface is `he*`.
4. **Block vs single-line `if`**; a trailing `\` continues a line. Naive counters
   false-positive on these; do not "fix" valid code.
5. **`itemDelimiter`/`lineDelimiter` are global:** set them before every parse
   (engine note 2.3). `heLobbySetVisible` restores it mid-fold since v0.25.3.
6. **Constants must be literal** (unified check 22 refuses a non-literal value;
   engine note 1.3).
7. **A command called with `()` throws** "error in function handler" and its body
   never runs (`heProbeSodium()`, v0.10.x). Unified check 16; `heFoo (x), y` is
   legal (engine note 3.4).
8. **Custom properties are text;** booleans are `"true"`/`"false"`.
10. **Dangling else:** a bare `else` after a single-line `if` binds to it
    (unified check 20).
11. **Declare locals at handler top.** A house convention for this file: the
    checker gates nested `variable` only in `.lcb`, and mid-handler `local` is
    legal LiveCodeScript.
13. **Object tokens are single words** (`audioClip`); the message box container
    is `msg`, never "the message box" (v0.17.1; unified check 18).
14. **Sensor/contact messages go to `b2kContactTarget`**, not the frame target.
17. **`b2kSetVelocity` wakes the body:** one toss, then let it sleep.
19. **`b2kSpriteOnFinish` is the Kit's SETTER, never a receiver.** The wiring
    has three parts: `b2kFrameTarget me` once, `b2kSpriteOnFinish tSpr,
    "heCardFlipDone"` per sprite, and `on heCardFlipDone pSpriteRef, pAnimName`
    gated on its own context lock (a stale finish must not double-fire a flip).
    The dead `on b2kSpriteOnFinish` receiver was removed at v0.24.1; the flip
    chaining it was written for is unbuilt.
23. **Sprites do not rotate:** flips are squash frames; anything that tumbles is
    a graphic body.
24. **Mixed sprite families need `b2kSheetScale`,** and some frame names carry
    `.png`.
27. **`the result` is consumed by the next command:** capture it at once.
29. **A constant must be declared before its first use, lexically** (unified
    checks 4 and 19; 19 was the `heTestDealRun` defect).

### 3.2 Member traps

- **Traps the fold found in the Level 0 deal path (2026-08-15).**
  `heXorSeedsHex` used `repeat with ... step 2`, and OXT ignores the increment
  (engine note 3.1): 63 overlapping pairs, a wrong-but-consistent deck.
  `heDeckFromStreamKey` re-threw inside a `catch`, and that throw never reaches
  the caller (engine note 3.2). Both rewritten; the Python KATs pin the
  2-stepped semantics.
- **The playable path and binary (CORRECTED).** v0.2.0 made the practice deal
  binary-free after repeated double/binary conversion throws: Park-Miller
  MINSTD, integer-only, every product < 2^53, seeded from `sxRandomUniform` or
  from time + `random()`, labelled "practice". Since then `heHandStart` deals
  the Level 0 committed keyed-stream deck whenever SodiumXT is present (seeds
  from `sxRandomBytes`, hex at the edge, `heLevel0Deck`), inside a `try` that
  falls back to the practice PRNG, so the playable path can never break.
  Hotseat is tamper-evident, not unstackable: one node holds every seed.
- **Wire arity (2026-09-09).** A wire is EXACTLY ten tab fields. The sender signs
  items 1-6 and the host 1-9, but `heNetApplyWire` hashes the WHOLE line, so a
  trailing field forks the victim's chain unrecoverably. `heEnvVerify` drops any
  line that is not ten fields, before decode, and refuses a last char that is a
  tab, because the engine ignores one trailing delimiter when counting (engine
  note 2.2). A legal wire ends in a 128-hex host signature. Four harness checks
  pin both directions; they have not yet met an engine (the v45 run owes them).
- **Both operands are evaluated (engine note 2.5).** `heBetApply`'s refusal
  `X is not a number or X is not trunc(X)` evaluated `trunc("abc")`; it is
  nested now. Whether `trunc` of a non-number throws on the engine is
  unrecorded.
- **KNOWN EDGE (recorded, not engineered away).** A timeout drained from the
  REORDER BUFFER can be early-refused by the client that just learned of the
  turn: fail-visible, disputed at the settle, healed by reconnect.
- **Recent fixes, as rules.** v0.25.3 (the 2026-08-27 engine finding): the
  handStart fold calls `heLobbyHide`, and `heNetStartGame`'s refusals land in
  the lobby's own net feed. v0.24.5: History had summed total commitment (2400
  shown for a 784 pot); `heAwardedPot` is the rule, pinned five ways and
  mirrored in fold-kat. v0.3.0: the dead-button rule, the BB always advances to
  the next live seat (`heScheduleButton`, TDA rule 10; pinned in betting-kat
  and the harness).

## 4. Layer contracts

**Level 2 compute (v0.19.0).** `kHeDomainL2Card` = `"HOLDEM-L2-CARD-v1|"`;
`out[j] = k * in[sigma[j]]`; the doer and the showdown verifier are the same
handler. Every seam is lowercase hex. Every failure is a DISTINCT `"void:..."`
string, never a throw, with each `sx*` call in its own `try` with declared catch
locals. `heL2HasRistretto` is the cached ABI-8 probe (a pre-ABI-8 SodiumXT
throws "can't find handler"). The validity predicate runs FIRST in
`heL2MaskPointHex`, because scalarmult conflates invalid-point and
identity-result; keep that order. None of this is wired to a played hand, the
UI or the wire yet.

**Batched mask step (v0.25.0).** On ABI 9, gated on `heL2HasDleq()`, a
shuffle-mask step costs 4 FFI crossings (hex2bin scalar, hex2bin concatenation,
one atomic `sxRistrettoScalarMultBatch`, bin2hex) against the per-point loop's
~312. The loop stays as the pre-ABI-9 path AND the refusal path (any batch throw
re-derives through it, so the void strings never change). Section 16 pins batch
== loop on the KAT deck; a corrupted point voids with its position.

**Void-and-audit and DLEQ (v0.22.0).**
- The record formats are pinned consensus surface: `shuffleStep`
  `pos=,ck=,deck=` (points `|`-joined, ck = k*B) and `unmaskStep`
  `pos=,slot=,val=,proof=` (proof = a1||a2||z). A byte change is a consensus
  break: pins move and `kHeHarnessV` bumps.
- The machine is pure and latched, and frozen after any void. The signer
  position comes from the VERIFIED envelope. An identical re-post of the last
  applied record is `dup`; a DIFFERENT step for a filled position is named
  equivocation, so keep transport dedup in front. Attribution is direct
  (`named=pos`) for publicly refusable records and deferred (`named=audit`)
  for final-not-in-table.
- `heL2VoidAudit`'s order is normative: ck binding, then per-contributor shuffle
  re-verification, then chains in slot order. A staller keeps its name only if
  everything signed re-verifies.
- Reduce every scalar mod L (ScalarAdd-zero) before any point mult, and REFUSE a
  non-canonical z. The DLEQ nonce is derandomized under `kHeDomainL2DleqW`;
  never use a random w. Transcript hashes see LOWERCASED hex. The verifier
  batches c*ck + c*P2 in ONE crossing (z*B and z*P1 cannot join it).
  `heL2HasDleq` is the cached ABI-9 probe; below ABI 9 the audit runs minus the
  binding, and section 19 skips the DLEQ half by name.

**Onion tables (2f, v0.20.0).**
- All protocol work happens on the poll tick: `heOnionStatus`, `heOnionPeer`
  and `heOnionStreamEvt` only stash; `heNetOnionTick` does the rest. Every
  `ox*` call sits in its own `try` with a declared catch; the `kHeOnion*Ticks`
  watchdogs guard every wait. Fail closed and never fall back.
- Tor is assumed running on 9050/9051; Tor Browser alone exposes no control
  port, and the message says so. `heJoinRefusal` is pure.
- The invite is `<64hex>@<56base32>.onion`: one word and non-hex, which gives
  downgrade refusal by format. The address comes from `heOnionSeedHex` under
  `kHeDomainOnion`, computed offline at create (SodiumXT ABI 6 for the
  deterministic onion, ABI 7 `sxSha3_256` for the offline address) and
  cross-checked against `oxServiceAddress` at publish.
- The `h` hello stands in for the rp1 handshake: verify-or-drop, and the host's
  hello precedes the replay. LF framing is safe because every free-text field
  is hex; one wire line per `oxWrite`.
- H1: streams and the service close on leave/stop; the control connection
  survives between tables and gets `oxShutdown` on closeStack (`gOxCtlUp`).
- onionxt is carried with NO `DROP_HANDLERS` entry on purpose: this stack
  defines no socket handlers, so OnionXT's `on socket*` wrappers must ride along
  or its sockets hang silently. `heHasOnion` stays a live probe (false = a
  damaged embed, still fail-closed).

**Oracle and the 2e remainder (v0.21.0).**
- Street ckpts sign the TRANSITION wire's head: the last holeDeliver for deal,
  the street's board wire, the betting-closing wire for showdown. Never sign
  "whatever the head is now". The `s?` seq is a trim hint, never an authority;
  the reconnect handshake still replays in full.
- show/muck are display-only by construction (policy in react step 11b,
  mirrored in fold-kat). `heNetLogToHotseat` re-derives and never invents.
- The oracle is the host role minus the seat. `level=1` in the signed cfg is its
  only marker, and dealLevel carries `level=1,dealer=0`. Seams:
  `heNetDealerPubHex`, `heNetWeDeal`, `heNetContribCount`, `heNetMyContribPos`,
  `heNetContribPosOk`. The oracle owns position dealCount+1, holds no seat,
  stack or receipt signature, and its audit files as "oracle" (slot 0). An onion
  oracle's seed uses `kHeDomainOracle`, never `kHeDomainOnion`.
- Oracle loss IS host loss, with one 60 s wire-silence watchdog.
  `heElectHostOf` takes the lowest live seated pubkey; the candidates come from
  `heNetElectablePubs`: seated, holding chips, not the lost host, and NOT
  sitting out (v0.24.4: electing a sat-out seat was a deterministic table
  death). Sit-out is transcript-derived, so it may gate the election;
  per-client observation may gate seating, never an election. The election
  never guesses or negotiates.

**Liveness (v0.23.0, corrected v0.24.0, engine-found v0.24.2/v0.24.3).**
- A timeout is a FIELD on the existing act/bid wire (`seat=/timeout=1/bank=`),
  never a new kind (protocol-kat seq 10..13). No deadline crosses a wire; the
  cfg carries `act=/bank=/miss=` (`heNetCfgVal` defaults).
- `heNetTurnMark` restarts a clock only when the SUBJECT changes. turnKey
  carries hand-street as a 4th item the tick never parses (the v0.24.3 engine
  finding).
- Refuse a timeout more than `kHeActSkewSecs` (5 s) early; this is not the
  +-600 s window. The waiver keys on the clock's REPLAYED flag
  (`heNetTurnClockStart` during catchUpTo) as well as the seq waiver.
- `gGame["foldApplied"]` gates the bank spend, the miss count and the miss
  reset. The bank auto-arms on the first would-be timeout and is spent ON the
  wire (`bank=1`). A refused timeout re-arms (`heNetTimeoutRearm`) and never
  latches.
- Only a voluntary ACT resets the miss count; a bid is a forced post (the
  v0.24.2 engine finding). Sitting-out seats get limit 0 and are dealt out by
  `heNetNextOccList` / `heNetSeatedWithChipsList`. The plate says SIT OUT ahead
  of any countdown (`heSeatFaceLabel`). `sit` without `pub=` is a return. A
  parked table is latched (`gGame["handWait"]`); `heNetHandKick` clears the
  latch BEFORE emitting.
- Late-join seats ascending pubkey into the lowest empty seat, capped by cfg,
  and requires PRESENCE: `heNetPubIsLive` (a transport handle plus
  `gGame["seenMsByPub"]`). `kHeSeatLiveSecs` = 600 s (owner-accepted
  2026-08-16).
- The redial never races the election: the 60 s watchdog keeps counting, every
  step gates on hostLost, `heNetOnionStandDown` is quiet on both exits, and
  `heNetOnionDialFail` owns the fork. **Nothing may tear down the transport while
  hostLost is false and gameOn is true.** Redial: 4 attempts at 2/4/8/16 s
  backoff, 10 s per dial; a host-signed wire APPLYING resets the counter; the
  trailing seq is item-1..3 compatible, and `heAdmitTokenVerify` never reads
  past item 3.
- **Spectators DEFERRED 2026-08-16** (owner: "we do not need spectators at this
  point"). Joining a table with a free seat seats you with no way to decline,
  because every client sends role "player". Picking spectators back up needs a
  wire/UI decision, not a code fix.

**Layout.** `kHeStackRect` is 1024x640 (v0.23.0, inside the 720p budget). The
pot line sits BELOW the board: the centre column above it is seat 4's cluster
and bet chip. `tools/check-table-layout.py` re-derives all 159 control rects
(`check-stack-size` gates only the window); the eye is the OXT pass's.

## 5. The harness, the suite fold and the execution gate

**Two entry points, one run.** `heRunSelftest` is interactive: report panel,
clipboard and `msg`, ending `==== n pass, m fail, k skip ====`. `heSelfTest()`
is quiet: it returns the report with the first line `n passed, m failed`
(riptide's `rsSelfTest` shape), builds no control, never touches the clipboard,
and sweeps pending `heNet*` sends. Both drive `heTestRunAllSections`, 25
sections in run order: 1 Evaluator, 2 Betting, 3 Ante, 4 Level, 5 Legal,
6 Schedule, 7 Shuffle, 8 Fold, 9 Crypto, 10 Receipt, 11 Deal, 12 DealOrder,
13 Lobby, 14 NetSim, 15 NetPlay, 16 Level2, 17 Onion, 18 Oracle, 19 Level2Void
(the 4e bots), 20 Liveness, 21 Helpers, 22 Leaf, 23 Leaf2, 24 Leaf3 (the
consensus-critical leaves, 2026-09-24), 25 `heProbeSodium` (which ends with a
bare `put tRpt`, so it writes `msg`; deliberate, harmless).
The 5 member skips are the live legs (tor table, three-machine oracle round,
onion-hosted oracle, live timed table, tor redial), printed on a second line
`stMergeReturned` does not parse, so the suite skip total excludes them.

**Suite fold contract (the NINTH folded harness, 2026-08-16).** Prefix `he1`,
entry `he1heSelfTest`. It is a PREFIXED fold, not a verbatim embed, because the
game and its tests are one file and `rename()` moves both sides: all 165
constants come out byte-identical, and rename touches only 45 of 6,950
literals. A verbatim embed would collide on `openStack`/`closeStack`/`mouseUp`,
and `on b2kFrame` would receive the embedded Kit's frame messages during
box2dxt's hand-stepping.
- **Nine chrome handlers are dropped:** `openStack`, `closeStack`, `mouseUp`
  (the shared `DROP_HANDLERS`) plus `drop_extra`: `preOpenStack` (it sets rect
  and title and would turn the suite window into a 1024x640 stack called
  "holde-em") and the five scrollbar messages guarded on `heBetSlider`.
  `drop_extra` is asserted, so renaming one here fails the build.
- **One rewrite:** `heTestSweepNetTimers` sweeps `begins with "heNet"`, and a
  FRAGMENT of a name is never renamed. The generator substitutes the member
  prefix through `@PREFIX@`. That widening deliberately also catches
  `heNextHandTick`, `heRevealStep`, `heRunoutStep` and `heSettleStep`; a stray
  next-hand tick would DEAL A HAND in the core's async phase. Standalone keeps
  the narrow stem, because a real table's HUD must survive a harness run.
- **The fold CUTS the embedded onionxt span** (`strip_spans` on the holdem
  row): the paste already carries that layer once, verbatim.
- **Asserted by `check-suite-selftest.py`.** Check 7d refuses these as reachable
  from `he1heSelfTest`: `heNetStart` (a second libtorrent session),
  `heRunSelftest`, `heBuildTable`, `heReportShow`, `heKitTryInit`. `heNetStop`
  IS reachable (`heTestLivenessRun` -> `heNetOnionDead` -> `heNetOnionFail`) and
  calls `btStopSession gGame["session"]`; that is harmless only because
  `gGame["session"]` is written solely by `heNetStart`; keep it that way. The
  closure must create and delete no controls, never resize or retitle the
  stack, and never touch `clipboardData`; the sound path fails closed in a paste
  (`heStackFolder` empty, `gSndOk` never set). One benign residue: `set the
  defaultStack to the short name of this stack` is not restored. Check 7e
  refuses the dropped handlers reappearing.

**The KATs are MIRRORS.** Ported line for line, they prove the port matches the
engine, not that the rules are right. `tools/logic-fuzz.py` drives the same
mirrors against an INDEPENDENT evaluator and side-pot settlement: all 2,598,960
five-card hands exhaustively (exactly 7462 classes), ~90k fuzzed configs with
fixed seeds, and whole-game invariants (chip conservation, no negative stacks,
termination). Since 2026-08-23 (backlog A5) it also property-fuzzes L2
void-and-audit attribution (honest never voids, a void names exactly one
contributor, the named one is the injected one), against protocol-kat's
`l2_void_*` TWIN, not the xTalk. A full run is ~80 s, `--quick` ~16 s. It is the
required backing for any "verified sound by property tests" claim.

**The execution gate (2026-09-11).** `tools/check-script-vectors.py` runs the
shipped stack's `heTestRunAllSections` through riptide's runner (siblings
`../riptide/tools/check-demo-boot.py` and `riptide_reference.py`, which load
nostrxt and coinxt; resolved by `sibling()` / `XTALK_SIBLINGS`). SodiumXT is
modelled: BLAKE2b, ed25519 and X25519 are faithful; the sealed box is a MODEL;
